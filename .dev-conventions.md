# Development Conventions

## Commit Style
- Concise messages describing WHAT changed, not HOW
- Frequent small commits per logical unit
- Format: `feat: <description>` or `fix: <description>`

## Code Quality
- Type hints on all public functions/methods
- Google-style docstrings for all public APIs
- ruff linting + mypy type checking before commit
- No emojis, no unnatural language in comments/specs
- No third-party HTTP client in the core pipeline (stdlib urllib only);
  numpy is the sole numeric dependency

## Project Structure
```
coderag/
  config.py        # env-driven settings (local model endpoints)
  models.py        # Chunk / Source / RagResult dataclasses
  main.py          # FastAPI demo server entry point
  routers/         # /api/ask, /api/status
  services/
    ingestion.py   # AST-based codebase chunking
    embed.py       # Ollama /api/embed batch embeddings
    retrieval.py   # numpy cosine top-k index
    synthesize.py  # LM Studio chat (grounded, cited)
    pipeline.py    # CodeRAG orchestrator + cached index
frontend/
  index.html       # single-page ask demo
tests/             # pytest coverage >=80%
docker-compose.yml # local dev setup
```

## Scope Boundaries
- Local, private by design: binds 127.0.0.1, never publicly hosted
- Local models only: Ollama (embeddings) + LM Studio (chat)
- Indexes Python source into per-symbol semantic chunks
- Grounded answers with source citations; degrades honestly when a model is offline

## Model Notes
- LM Studio's local Qwen is a reasoning model. Always send
  `"reasoning_effort": "none"` so the answer lands in `content` (not
  `reasoning_content`) and returns quickly.
